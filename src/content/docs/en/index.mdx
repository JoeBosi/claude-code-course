## Why this course

Claude Code is an **[agent](/en/glossario/#agent)**: an AI that does not just make suggestions, it acts —
it reads your project's files, runs commands in the [terminal](/en/glossario/#terminal), edits the
code, checks the result and corrects itself until the job is done. It changes the way software is
built, and the old habits are no longer enough.

This course takes you from the first installation to the workflows that are actually used in
production: managing the AI's memory, the `CLAUDE.md` instructions file, the extensions
(skills, MCP, hooks, subagents — each explained in its own module, and all of them in the
[Glossary](/en/glossario/)), headless automation and reusable project templates. Every module ends with links
to the official documentation: they are the map for going deeper and the place to read about what's new.

## Prerequisites

The only hard requirement is **a Claude account with an active plan** (Pro, Max or Team). The course
always uses the account login: a paid API key is never needed, and never asked for.

These help, but **are not mandatory**:

- **Familiarity with the terminal** — you can move between folders, run commands, read an error.
- **The basics of git** — commit, branch and diff, at least as concepts.
- **Node.js installed**, for the hands-on examples in some modules.
- **macOS or Windows**: every command is given in both versions, zsh and PowerShell, with the choice
  of operating system synchronized across all pages.

No previous experience with AI agents or with Claude Code is needed: we start from zero.

<Aside type="tip" title="Not a developer?">
You can still follow the course. Start with **[The basics](/en/basi/)** — ten minutes on the terminal, git, file
formats and how an AI model reasons — and keep the **[Glossary](/en/glossario/)** open: every technical
term in the course is explained there in one sentence, with an analogy. Inside the modules, the more
technical steps have a collapsible *"Starting from zero"* box with the minimum explanation you need to keep going.
</Aside>

## How to read the modules

Every module always has the same structure, so you know what to expect: estimated time and prerequisites,
objectives, key concepts, a step-by-step guided example with the expected output, an exercise with the
solution in a collapsible block, common mistakes and troubleshooting, a final cheat sheet and the official
sources consulted, with the date they were checked.

And the course runs on **two tracks**: the main text is written for developers, but every technical
term is linked to the [Glossary](/en/glossario/) on its first occurrence, and the steps that assume
developer knowledge have a collapsible *"Starting from zero"* box with the minimum explanation needed
to follow along. Those who know skip them; those who don't never get lost.
